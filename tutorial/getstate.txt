invoke() vs getState()

Ye difference yaad rakhna:

Method	Purpose
invoke()	Graph ko run karta hai
getState()	Saved state ko read karta hai

Example:

await addProcess.invoke(...);

➡️ Graph execute hoga.

await addProcess.getState(config);

➡️ Graph execute nahi hoga. Sirf existing checkpoint/state read hogi
--------------------------------
==================================================

getState() ke next step mein getStateHistory() samjho.

1. Difference
getState()
    ↓
Latest/current state

getStateHistory()
    ↓
Same thread_id ki previous states/checkpoints

in your case:
thread_id: priya123

ke andar jitni graph executions hui hain, unki checkpoint history retrieve kar sakti ho.

# first understand checkpoint =>
1. Pehle checkpoint ko samjho

Tumhare paas:

const history = await addProcess.getStateHistory(config);

Har iteration mein:

for await (const checkpoint of history) {
    console.log(checkpoint);
}

checkpoint ek saved state snapshot hai.

Iske andar mainly hum 3 cheezein dekhna chahte hain:

checkpoint
├── values      → us time ki graph state
├── config      → checkpoint/thread identification
└── metadata    → execution ke related information
2. Ab ye code run karo

Apne existing history code ko temporarily isse replace karo:

const history = await addProcess.getStateHistory(config);

for await (const checkpoint of history) {
    console.log("\n==============================");
    console.log("CHECKPOINT CONFIG");
    console.log("==============================");

    console.log(checkpoint.config);

    console.log("\n==============================");
    console.log("CHECKPOINT METADATA");
    console.log("==============================");

    console.log(checkpoint.metadata);
}

Run karo.

Tumhe kuch is type ka output milega:

CHECKPOINT CONFIG
{
  configurable: {
    thread_id: 'priya123',
    checkpoint_ns: '',
    checkpoint_id: '...'
  }
}

CHECKPOINT METADATA
{
  source: 'loop',
  step: 1,
  ...
}

Exact fields/version ke according output thoda different ho sakta hai.

4. checkpoint_id kya hai?

Ye aur interesting hai.

Ek hi thread_id ke andar multiple checkpoints hote hain.

Isliye LangGraph har checkpoint ko identify karne ke liye checkpoint_id use karta hai.

Conceptually:

thread_id: priya123

checkpoint_id: A
checkpoint_id: B
checkpoint_id: C

Yaani:

thread_id
   ↓
Conversation identify karta hai

checkpoint_id
   ↓
Us conversation ke particular saved state ko identify karta hai
5. Metadata kya karta hai?

metadata mein LangGraph execution/checkpoint ke context ke baare mein information rakhta hai.

Example:

metadata
├── source
├── step
├── writes
└── ...

Important: exact metadata fields ko assume nahi karna chahiye; tumhare LangGraph/package version ke output ko dekhkar hi unka meaning interpret karenge.
